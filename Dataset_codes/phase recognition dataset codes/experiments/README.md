# experiments/

実験案ごとに、コード・データ・条件の定義・実行結果・記録を1つのフォルダにまとめる場所。
このフォルダの外にある既存のファイル（`training/`, `evaluation/`, `data/`, `result/` など）は
「以前の実験」として扱い、ここからは**読むだけで変更しない**。

## 実験案の一覧

| フォルダ | 案 | 目的 | 状態 | 開始日 |
| --- | --- | --- | --- | --- |
| `planB_fixed_split/` | 案B | 既存の test 11症例を保ったまま、条件をそろえて学習し直したモデルどうしを比べる | 準備中（分割ファイルのみ作成済み） | 2026-10-03 |
| `planA_resplit/` | 案A | 案B の設定を固定したあと、分け直したデータで確認する | 未着手（実施するかは案B の後で決める） | — |

## 各案のフォルダの構成（共通）

```
plan<記号>_<目的>/
├── README.md     目的、決定事項、未決定の条件、ファイルの役割
├── conditions/   入力条件の定義（条件ごとに1ファイル。条件タグがファイル名）
├── scripts/      コード。ファイル名の先頭の番号が実行順（例: 01_build_case_split.py）
│   └── lib/      その案の中で共通に使う部品
├── data/         分割ファイルや窓の一覧など、小さな CSV と作成の記録（*.meta.json）
├── frames/       元動画から取り出した画像（大きいので git の管理対象外）
├── runs/         学習・評価の1回ごとのフォルダ: <日付>_<条件タグ>_<モデル>_seed<番号>/
└── notes/        実験記録（日付ごとの Markdown）
```

フォルダは必要になった時点で作る（まだ使っていないフォルダは存在しないことがある）。

## 命名規則

- 案のフォルダ: `plan<記号>_<目的>`
- スクリプト: `<実行順の番号>_<動詞>_<対象>.py`
- 入力条件: 条件タグで表す（例: `f30_i333ms_s5s_aa-on` = フレーム30枚・間隔1/3秒・窓の間隔5秒・antialias あり）。
  条件の全ての値は `conditions/<条件タグ>.yaml` に書く。
- データ: 条件に依存するものは名前に条件タグを入れる。依存しないものには入れない。
- 実行結果: `runs/<日付>_<条件タグ>_<モデル>_seed<番号>/` に、使った設定の写しを必ず入れる。

## 以前の実験のファイルとの関係

- 既存の部品（`models/timesformer.py`, `utils/gt_utils.py` など）は import して使ってよいが、中身は変えない。
- 中身を変える必要がある部品は、各案の `scripts/lib/` に新しく作り、README に参考にした既存ファイルを書く。
- 実行は、これまでどおり `phase recognition dataset codes/` 直下をカレントディレクトリにして行う。
