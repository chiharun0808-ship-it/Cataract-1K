# 案B: planB_fixed_split（既存の test を保った比較実験）

## 目的
既存の test 11症例・val 11症例をそのまま保ち、同じ条件で学習し直したモデルどうしを比べる。
既存のモデル（旧モデル・現行モデル）は、同じ test で測った**参考値**として並べるだけにし、
差の原因は主張しない（2026-10-02 合意）。

期間: 進捗報告までの約20日間（2026-10-02 から）。その後、案A（分け直したデータでの確認）を行う予定。

## まだ決まっていないこと（案B の本番の条件）

下の「再調査」で使った条件は、既存の結果を確かめるためのもので、**本番の条件として決めたものではない**。

| 条件 | 現行モデルでの値 | 状態 |
| --- | --- | --- |
| フレーム数 | 30枚 | 未決定 |
| サンプリング間隔（1つの入力の中のフレームの間隔） | 1/3秒 | 未決定 |
| 時間幅（上の2つで決まる） | 約9.67秒 | 未決定 |
| 学習の窓の間隔（stride） | 5秒 | 未決定 |
| 推論の間隔 | 1秒 | 未決定（評価指標と一緒に決める） |
| antialias（縮小の方法） | 学習はあり・推論はなし | 未決定（再調査では「あり」を使用） |
| 縦横比の扱い | 512×384 を 224×224 に押し込む | 未決定（再調査では中央切り出しを使用） |
| 画素値の正規化 | 0〜1 にするだけ（事前学習の重みは平均・標準偏差での正規化が前提） | 未決定（再調査では ImageNet の正規化を使用） |
| 画像の保存形式 | mp4v で再エンコード | 劣化しない形式（PNG）にする方針。どのフレームを保存するかは上の条件で決まる |

## 再調査：現行モデル（91.4%）を、不具合を直した状態で学習し直す（2026-10-04〜10-05）

分岐したセッション（作業用ツリー `planB-baseline-reproduce`）で行った。**目的は既存の結果の確認で、案B の本番の条件を決めたものではない。**

- 計画と結果のまとめ: https://claude.ai/code/artifact/12fa2746-de11-4136-98db-b5147844eb4b
- 実験設定の比較表（先行研究・他の手術の論文・現行モデル・再調査モデル）: https://claude.ai/code/artifact/f527c5ab-ca09-43b1-82b6-4e44ea042f21

### 決めたこと（分岐したセッションでユーザーが承認。日付は日本時間）
| 日付 | 内容 |
| --- | --- |
| 2026-10-04 | まず「不具合の修正だけ」（2症例の追加、mp4v の再エンコードをやめる、antialias のずれを直す）で再調査する計画を承認。50エポックを1回で通し、patience 10、seed 0 |
| 2026-10-04 | 「不具合のない実験」にするため、前処理も事前学習の前提にそろえる案（②）に変更。切り出しは中央の 224×224（a）。不具合の修正だけの条件（`repro-baseline_…_aa-off`）は学習に使わず、採用しなかった |
| 2026-10-04 | 学習の開始を承認（9:21 開始、26エポック目で early stopping） |

条件ファイル `defectfree_…_vitprep.yaml` には決定日が「2026-10-05」と書かれているが、会話の記録では 10/04（日本時間）の決定。まとめのドキュメントでも「要確認」としている。

### 変えたこと（現行モデルとの違い）
- case_5353・case_5357 を train に追加（56症例）
- 学習の画像を、mp4v の再エンコード動画ではなく、元動画のフレーム（PNG、劣化なし）にした
- 前処理を学習・推論とも `torchvision` の `ViT_B_16_Weights.DEFAULT.transforms()` にした（短い辺を256に縮小（antialias あり）→ 中央の224×224を切り出し → ImageNet の平均・標準偏差で正規化）
- 学習を「15＋35エポック（再開あり）」から「50エポックを1回で通す、patience 10」にした
- seed を 0 に固定した
- 変えていないこと: フレームの選び方（30枚・1/3秒間隔・窓の間隔5秒・末尾フレームのラベル）、optimizer（Adam、lr 1e-5、weight decay 0）、batch 1×8、勾配クリップ 1.0、クラス重み、データ拡張なし

### 確認の結果（学習の前）
| 手順 | 結果 |
| --- | --- |
| 02 現行モデルの再現 | 全4,387時点で保存済みの予測ログと完全に一致（91.36%） |
| 03 窓の一覧 | 既存の4,240窓がすべて一致。追加2症例は151窓（すべて train） |
| 04 画像の取り出し | train・val 45症例の53,326枚（約13GB）。すべて元動画の画素と一致 |
| 05 入力の一致 | 180窓すべてで、学習側と推論側の入力が数値として完全に一致 |

### 結果（test 11症例、同じ4,387時点）
| 指標 | 現行モデル | 再調査モデル |
| --- | --- | --- |
| 一致率 | 91.36% | 82.79% |
| 動画全体の macro F1 | 0.867 | 0.760 |
| 予測の切り替わり回数（正解は352回） | 517回 | 327回 |
| val の最良 F1 | 0.855 | 0.759（16エポック目） |

- 11症例すべてで一致率が下がった（症例ごとの差の平均 −9.0ポイント）。
- 増えた誤りのほとんどは、切り替わりの前後で起きる「隣接」の誤り（特に idle が絡むもの）。非隣接の誤りはほぼ変わらない（126 → 131）。
- 中央の切り出しが主な原因だという仮説は、強くは支持されなかった（`analyses/idle_confusion_edges/`）。
- 下がった原因（学習の進め方、乱数、前処理全体の変化など）は分かっていない。
